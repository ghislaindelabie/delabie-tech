# Security review — PR #33: Phase 6 — redirects + performance + a11y

**Date:** 2026-06-05
**Reviewer:** local security review (Opus) via general-purpose subagent acting in security role.
**Scope:** 5 commits — legacy-URL redirect stubs (jekyll-redirect-from), self-hosted webfonts (6 woff2 binaries + fonts.scss + forked `_data/origin/cors.yml` + head preloads + async FontAwesome), WebP images with reserved dimensions, a11y fixes (anchor labels via inline script, contrast, link underlines), two new structural specs.

## (1) What was reviewed

- Redirect stubs for open-redirect exposure — all `redirect_from` values fixed, owner-authored, same-site; meta-refresh targets are fixed permalinks.
- The inline anchor-label script — i18n string through `jsonify` into a JS literal.
- Binary asset provenance (woff2 from fonts.gstatic.com, SIL OFL; WebP generated locally from in-repo originals).
- Forked `cors.yml` — third-party libraries remain pinned to exact jsdelivr versions; no loosening.
- Inline `onload` media-swap handler on the FontAwesome link.

## (2) Security-relevant decisions

- **Self-hosting fonts removes the fonts.googleapis.com / fonts.gstatic.com origins** — no visitor IP disclosure to Google (GDPR posture improvement aligned with the site's positioning).
- Redirect stubs carry `noindex` + canonical to the destination — no duplicate-content or redirect-chain abuse surface.
- No CSP is configured; the new inline handler and script would need a nonce/hash if one is ever added (noted for pre-cutover hardening, not a current issue).

## (3) Findings

No CRITICAL, HIGH, MEDIUM or LOW findings.

Revisit if i18n data ever gains a non-owner source |
