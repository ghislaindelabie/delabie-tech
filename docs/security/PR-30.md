# Security review — PR #30: Phase 5 SEO surface + email privacy

**Date:** 2026-06-04
**Reviewer:** local security review (Opus) via general-purpose subagent acting in security role.
**Scope:** 6 commits, ~38 files. Liquid templates emitting JSON-LD / meta tags / analytics (`_includes/{schema-person,archive-jsonld,analytics-goatcounter,metadata-hook,head}.html`), identity data (`_data/schema_person.yml`), `_config.yml`, Liquid-generated `sitemap.xml`, `assets/robots.txt`, CV/contact content pages, two teaching items + one archive item, four new structural specs, Playwright helper. No CI workflow changes.

## (1) What was reviewed

- JSON-LD emitters for `</script>`-breakout / injection risk — every interpolation path from frontmatter and `_data/` into `<script type="application/ld+json">` blocks.
- seo-tag capture-and-rewrite logic in `head.html` (BlogPosting strip on `archive_item`).
- Third-party analytics loader (`gc.zgo.at`) — gating, key handling, transport.
- PII exposure against the repo's email/phone privacy invariant.
- Secrets in config/data files.
- `robots.txt` + `sitemap.xml` stance on the noindex preview host.

## (2) Security-relevant decisions

- **Email/phone privacy invariant strengthened**: `social.email` removed from `_config.yml`; every `mailto:` on CV pages replaced with `/contact/` links; new `tests/structural/email_privacy_spec.rb` enforces zero email / phone / `mailto:` / `tel:` patterns in the built `_site/` — template-level, content additions can't regress silently.
- **JSON-LD escaping**: `schema-person.html` routes all interpolated strings through `| jsonify` (dates stay raw — machine-formatted); `archive-jsonld.html` brought to uniform `jsonify` coverage during this review (`url`, `inLanguage`, `isBasedOn`, `about.*`).
- **Analytics**: GoatCounter script loads only on exact production hosts (apex or www), explicit `https://`, renders nothing while `analytics.goatcounter.code` is empty. No cookies / PII per vendor model.
- **GSC verification hook** renders only when `seo.google_site_verification` is set; empty in committed config — the token is pasted at cutover, and a GSC verification token is not a secret.
- **Threat model** (carried from PR #22/#23): static Jekyll site, owner-authored content only, Liquid runs at build time, no backend, no untrusted input boundary.

## (3) Findings

No CRITICAL, HIGH, MEDIUM or LOW findings.

## (4) Risks accepted with rationale

| Tag | Severity | Risk | Rationale |
|---|---|---|---|
| SEC-N1 | NONE (noted) | A literal `</script>` in owner-authored frontmatter could have broken out of raw-interpolated JSON-LD fields | Resolved during review — uniform `jsonify` applied; values were owner-authored only, so no attacker path existed |
| SEC-N2 | NONE (noted) | GoatCounter script has no SRI hash | Analytics CDN ships rolling updates; SRI would break on every release. Exact-host gate + HTTPS + reputable vendor accepted |
| SEC-N3 | NONE (noted) | Open `robots.txt` + sitemap on the noindex preview host invites crawl of preview URLs | `noindex, nofollow` meta is authoritative for indexing; `robots_spec` forbids blanket `Disallow: /`; stance flips naturally at cutover |

## (5) Recommended follow-ups

- None blocking. Keep `jsonify` the default for any future JSON-LD field.
