## (2) Security-relevant decisions

- **`| escape` on author-controlled fields interpolated into HTML attributes** — `<img alt="{{ page.title | escape }}">` (`_layouts/archive_item.html:33`).
- **`| relative_url` on internal hrefs** — `pdf`, `cover`, `item.url` go through the filter (`_includes/archive-row.html:23,64,70`; `_layouts/archive_item.html:33,54`). Forces a leading `/` and prevents traversal escaping the site root.
- **`rel="noopener noreferrer"` on every `target="_blank"`** — both static (`_includes/archive-row.html:67`; `_layouts/archive_item.html:49,59`) and dynamic (`_includes/archive-row.html:32,46`).
- **URL/path schema gates tightened to forbid attribute-breaking bytes** — the structural rspec was strengthened during review. `original_url` and `wayback_url` now match `\Ahttps?://[^"\s<>]+\z`, `pdf` matches `\A/assets/pdf/archive/[A-Za-z0-9_./-]+\.pdf\z`. This neutralises the LOW findings below at the schema layer rather than at every call site.
- **Title link `href` fallback chain guarded** — `if title_href and title_href != ''` (`_includes/archive-row.html:45`) prevents `<a href="">` open redirect.
- **`{{ content }}` raw-HTML output gated by `page.detail`** — bodies are author-authored markdown, same trust model as `_publications/` and `_case_studies/`.

## (3) Findings

Three LOW findings surfaced during review, all addressed by the schema-gate tightening above. No outstanding HIGH or MEDIUM.

### Finding 1: `original_url` / `wayback_url` interpolated into `href` without scheme escape

- **Severity:** LOW
- **Category:** xss / open_redirect
- **Confidence:** 0.35 (low realism — requires malformed front matter committed by the author)
- **Status:** ✅ Resolved at schema layer.
- **Description:** Values interpolated into `href` without `| escape`. The original schema regexes (`\Ahttps?://`) did not forbid embedded `"` or `<>`, so a corrupted clipboard paste like `https://evil/"><script>` would pass build and inject markup at render time.
- **Resolution:** Tightened both regexes in `tests/structural/archive_collection_spec.rb` to `[^"\s<>]+\z` (`original_url`) and `[^"\s<>]*\z` (`wayback_url`). A malformed value now fails CI before it can ship.

### Finding 2: `pdf` `href` not escaped, `start_with?` + `end_with?` allowed embedded quotes

- **Severity:** LOW
- **Category:** xss
- **Confidence:** 0.25 (same low-realism shape)
- **Status:** ✅ Resolved at schema layer.
- **Description:** `pdf:` schema check was `start_with?("/assets/pdf/archive/")` + `end_with?(".pdf")`, which permits any byte in between including `"<>`.
- **Resolution:** Replaced with `\A/assets/pdf/archive/[A-Za-z0-9_./-]+\.pdf\z`.

### Finding 3: Author-controlled text fields rendered without `| escape` in HTML body

- **Severity:** LOW
- **Category:** xss
- **Confidence:** 0.10
- **Status:** ✅ Risk accepted.
- **Description:** `{{ include.item.title }}`, `{{ include.item.source }}`, `{{ include.item.excerpt }}`, `{{ tag }}` rendered as text content without `| escape`. The risk only materialises if the author writes literal HTML in front matter.
- **Rationale:** Matches the existing `_includes/publication-item.html` convention (verified). Static-site threat model: front matter is author-controlled, no untrusted-input boundary exists. Adding escape filters here would diverge from the publication-item pattern without adding meaningful protection.
